## Bounded stage-five regression requirements

The source contains the regression checks below. The [handoff](README.md) records the passing runs, final rendered review, measurements and the distinction between the complete browser run and subsequent focused CSS checks:

1. **Freeze the delivered span.** The combined retained fixtures cover 0–4.08 for landscape/portrait/short (the new stage-four fixture covers 2.25–4.08), including camera, target, pulse, up and conversion state; all eight old still locations are asserted separately. Retain 5.6 useful viewport heights per unit and therefore 22.848 before the extension. Older tests use a `STAGE_FOUR_END` boundary instead of letting their use of `JOURNEY_END` accidentally cover later business scenes with inverter-specific assertions.
2. **One authored state in either direction.** Sample both sides of every new chapter boundary, midpoints and dense interior positions. Check finite values, camera/aim/up continuity, intended C1 and exact reconstruction after reversal. Charging and discharging are mutually exclusive; import and export are mutually exclusive. Stored-energy state is bounded and changes in the correct direction only in its authored phase. Optical opacity stays zero.
3. **Connected assets, visible geometry.** Independently compare the existing AC endpoint to new distribution, converter and storage connection points; use actual transformed mesh bounds/triangles. Test route endpoints and camera/near-frustum clearance across three authored camera framings and five projection aspects; inspect focal hardware fit in rendered compositions. The actual-mesh diagnostic is `scripts/check-stage-five-clearance.mjs`; the Node regression invokes its bounded sampling pass. Do not exempt bad geometry because an opacity mask conceals it. Check supported cable placement and actual opaque depth in rendered frames.
4. **Readable stills and meaningful access.** Twelve stills now include business 4.70, storage 5.09, connected 5.56 and Aesir 6.03; browser coverage checks matching HTML, one selected control and frozen ambient time. The operation/illustration/optional-storage qualifications must be available in still views. Test small portrait, short landscape, 200% text and zoom, tab/Skip/focus and no overlap of labels, copy, focal equipment and controls. Keep no-JS service and direct application access.
5. **Owned resources and late completion.** Exercise every new lazy owner with delayed import, import failure, held GPU readiness, timeout and context loss. Readiness resumes the requested progress/still without another interaction; failure retains service access; rapid Skip stays at the application. Teardown cancels timers and cannot resurrect canvas, labels, objects or requests. Warm all new scenes/LOD/shadows before comparing repeated traversal resource counts; instrument actual disposal events and include every new overlay/instance buffer in owned budgets.
6. **Preserve external contracts.** Retain baseline byte parity, assembled page/API/anchor routing and mocked payment tests. No provider request, real application, payment, cart, email or deployment during tests. Known-defect reproductions remain defects, not launch acceptance criteria.
7. **Measure this build honestly.** Record source checkpoint and asset hashes, type/build/test counts, continuous forward/reverse native-scroll recording, five-viewport and enlarged-text captures, request totals, warmup latency separately from settled frame intervals, actual owner allocation estimates and named hardware/browser. Keep physical-device, thermal and provider-certification gaps explicit.
