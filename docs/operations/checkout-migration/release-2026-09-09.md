# Live release and operator handover — 9 September 2026

The new site is live at **https://aesirsolar.co.uk/**. `www` redirects to it, and the old public checkout now leads to the new application form. The complete application is saved before Stripe offers payment. Verified payment creates one private work item and queues an alert to **nick.frith25@gmail.com** from **hello@aesirsolar.co.uk**.

## What happens for an applicant

1. An applicant supplies the installation details and both consents. Unknown/out-of-scope screening leads to contact before payment. The server saves accepted details with the policy version and a stable reference.
2. Stripe Checkout offers exactly **£250 fee + £50 VAT = £300** for one suitable G99 Form A1-2 application. Repeated clicks or an interrupted return do not create duplicate paid work. Card details stay with Stripe.
3. A signed notification is independently checked against Stripe's payment record. A valid paid application creates one work item, even if the applicant closes the browser. The email gives Nick that work reference. Paying does not grant network approval or submit the G99 document to the network operator automatically.

## How Nick handles incoming work

- Open the private [Solar Table Editor](https://supabase.com/dashboard/project/gkxwaeoknypueqbcqhtl/editor) and select **solar_operator_queue**. Filter **livemode = true**. Existing `false` rows are sandbox fixtures and must never become real DNO work.
- Match the full reference in the alert. The `details` field contains the complete original application and additional suitability confirmations; `policy_version`, payment identifiers and payment time are alongside it.
- Review the supplied information/documentation and suitability. Contact the applicant when anything is missing. Preparation, submission and follow-up remain Aesir's service work; this release automates intake, payment verification, work creation and alerts.
- In **solar_work_items**, edit only the row with that `application_id`. Set `assigned_to`, useful `operator_notes` and the relevant status: `ready`, `in_progress`, `awaiting_applicant`, `submitted`, `completed`. Do not edit payment state, references, access tokens or financial evidence to move work along.
- Check the same reference before acting on any repeated email. Email delivery can repeat after an uncertain mail-server acknowledgement; the database still has one work item. Refunds or disputes must be handled from the matching real Stripe payment under the published policy, not by editing the database to pretend money moved.

The paid queue is the authoritative work list. An email is an alert, not the sole stored application. The public site has no customer account portal; existing applicants can contact hello with their reference. Sharing a receipt URL alone does not expose private application status.
